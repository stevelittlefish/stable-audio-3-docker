01The big picture

A LoRA is a small .safetensors file (~50–200 MB) that adapts a frozen base model to a target style. You're not retraining Stable Audio 3 — you're teaching it one consistent sound and getting a swappable, strength-adjustable adapter out the other end.

The critical insight for this project: the three stages don't share a runtime. Only the .safetensors file crosses between them, so training stays completely decoupled from your inference container.

The training tool is Underfit (Dadabots) — a web dashboard built on this same stack. It gives you dataset encoding, live loss curves, auto-resume, and demo generation for free. It swallows the whole training step so there's no GUI to build. It does not replace your stem service (prep) or your FastAPI server (serving) — those are yours.

02Hardware & the 3090

A dedicated RTX 3090 is more than enough, and dedicating it cleanly avoids fighting your inference services for VRAM.

ConcernRequirement3090 (24 GB, Ampere)
VRAMmedium-base needs ~6.5 GB; Underfit floor 8 GB✅ 3–4× headroom
bf16 trainingRequired (SA3 trains in bfloat16)✅ native on Ampere
Flash Attention 2Required by medium✅ supports Ampere — install a prebuilt wheel
CUDA / PyTorchtorch 2.7.1, CUDA 12.6 default✅ works with any modern CUDA

Because you have so much headroom, you can skip every low-VRAM compromise: train at full precision (no --base_precision bf16), use standard dora-rows (no need for lora-xs), and push rank higher (16 → 32) or batch size above 1 for steadier convergence.

One setup gotcha

Flash Attention 2 must be installed. Don't compile it — grab a prebuilt wheel matching your CUDA / torch / Python from the community wheels repo. The filename encodes the requirements (e.g. cu126torch2.7-cp310). Everything else in the stack is stock.

03Building the dataset

This is a style adapter, not a from-scratch model, so you need dozens of clips, not thousands.

  • Core (Limp Bizkit): lean on the Significant Other / Chocolate Starfish era where the sound is most defined — downtuned 7-string chug, funk-metal slap bass, DJ scratches, groove drumming.
  • Support (other nu-metal): mix in Korn, Deftones, P.O.D., Staind, etc. This stops a small pure-Bizkit set from memorizing specific riffs and helps the adapter generalize the style.
  • Target: ~30–60 instrumental clips total. A LoRA learns whatever is consistent across the set, so curate for one coherent sound.
The golden rule for backing tracks

A LoRA learns whatever is consistent in the audio. Feed it full tracks and it learns the vocals too — then tries to render vocal-like noise into your instrumentals. For backing tracks, the training set must be instrumental. That's what Stage 03½ is for.

03½Stripping vocals (LAN stem service)

Run every source track through your stem-separation-docker service first. Its two-stem mode returns exactly the no_vocals instrumental you want. It mirrors the SA3 submit → poll → download API shape.

# 1. submit — two-stem gives vocals + no_vocals (instrumental)
curl -s -F 'audio=@song.wav' \
     -F 'params={"mode":"two-stem","file_format":"wav","shifts":2}' \
     http://ai.lemon.com:5336/v1/separate
# -> {"job_id":"...","state":"queued"}

# 2. poll until state is done
curl -s http://ai.lemon.com:5336/v1/jobs/<id>

# 3. download the instrumental stem
curl -o instrumental.wav \
     "http://ai.lemon.com:5336/v1/jobs/<id>/stem/no_vocals"

shifts (1–10) trades speed for cleaner separation; 2 is a good balance, bump it if vocal artifacts bleed through. If you've set SEP_API_KEY, add -H "Authorization: Bearer <key>" (it's off by default).

04Clipping & curation

The training loader takes a random fixed-length crop of each file every time it's sampled, and there is one caption per file. That single fact decides how you clip.

Hand-built sections beat whole tracks

  • One caption is stretched across the whole file. Feed a whole song and your caption gets applied to random crops that may land on the intro, a quiet breakdown, or an outro — the model learns a blurry average.
  • Whole tracks smuggle in filler — silence, transitions, key changes — all trained under the same label. On a 30–60 clip set that dilution really shows.
  • Sections let you curate for strength and label accurately, so you can later steer between "verse groove" and "breakdown" because the model learned them as distinct.
Recommended shape

Core (Bizkit): hand-cut 15–30 strong ~20–40s sections, each labeled for what it is (verse groove / chorus riff / breakdown).
Support (other nu-metal): auto-chunk into ~30s pieces with lighter labeling.
Everything runs through the stem service first, so it's all instrumental.

Minimum length

Clips must be at least as long as the training crop window, or they get padded and wasted. Confirm the exact sample_size the trainer uses and size your minimum clip length to match.

05Labeling

Each clip needs a matching .txt caption (Underfit can also read JSON sidecars or audio tags). Consistent vocabulary is what ties your prompt to the sound — pick a trigger phrase and reuse it in every caption.

clip01.txt → "nu-metal backing track, downtuned 7-string chug riff,
              funky slap bass, hard groove drums, DJ scratches, 95 bpm"

clip02.txt → "nu-metal backing track, half-time breakdown, palm-muted
              guitar, heavy bass, aggressive groove, 80 bpm"
  • Keep the trigger phrase (nu-metal backing track) in every caption — it becomes the phrase you prompt with later.
  • Vary the specifics (bpm, breakdown vs. verse, scratches present or not) so the model learns the space, not one riff.
  • Don't over-describe per-clip details you don't want memorized.
Small-dataset tip

Exclude the duration conditioner during training (--exclude seconds_total) to prevent it being hijacked — a known small-dataset failure mode. Underfit exposes the same layer include/exclude controls.

06Training

Option A — Underfit (recommended)

Stand it up on the server, pinned to the 3090. It handles encoding (audio → latents), the training loop, live loss curves, checkpointing, auto-resume across disconnects, and auto demo generation so you can hear it improving. Point it at your folder of instrumental, labeled clips.

  • Pin it to the 3090 (e.g. CUDA_VISIBLE_DEVICES=<3090-index>) so it never touches the inference card.
  • Base model: medium. Adapter: DoRA (its recommended default). Rank 16–32.
  • Make sure checkpoints land somewhere the SA3 container can read — see Stage 07.

Option B — the built-in CLI

If you'd rather skip the dashboard, this repo ships scripts/train_lora.py. Same output format, fully compatible with the server.

uv sync --extra lora   # one-time

uv run python scripts/train_lora.py \
    --model medium-base \
    --data_dir ./my_data \
    --rank 16 \
    --adapter_type dora-rows \
    --exclude seconds_total \
    --steps 1000 \
    --save_dir ./lora_out

Start around 1000 steps, listen, iterate. Checkpoints drop every 500 steps into save_dir. Optional: pre-encode once with scripts/pre_encode_dataset.py to skip the autoencoder on re-runs.

Either way, the deliverable is the same: a lora_stepNNN.safetensors file.

07Serving from the FastAPI server

Your existing server supports LoRAs end-to-end — two touchpoints.

Load at startup

run_api.py takes --lora-ckpt-path (one or many). Copy the .safetensors into a volume the container mounts, add the flag, and rebuild.

uv run python run_api.py --model medium \
    --lora-ckpt-path /srv/loras/nu_metal.safetensors

# in Docker: mount the file, add the flag, then —
docker compose up -d --build
Remember

Loaded adapters are fixed per process — swapping a LoRA means a restart. And always rebuild with docker compose up -d --build so you don't ship a stale image. GET /v1/model lists what's currently loaded.

Control per request

Pass a loras array in the generate body — one entry per loaded adapter, in load order.

{
  "prompt": "nu-metal backing track, downtuned chug riff, funk bass, 90 bpm",
  "loras": [
    { "strength": 0.8, "interval_min": 0.0, "interval_max": 1.0, "layer_filter": "" }
  ]
}
  • strength — 0 disables, 1.0 full, >1 amplifies. Start around 0.7–1.0.
  • interval_min/max — gate the LoRA to a slice of the denoising process (early = global structure, late = fine detail).
  • layer_filter — disable named layers by substring.

No vocals in the training set, no vocals out — you get a clean instrumental backing track from your trigger prompt.

Note on source material

Training on commercial recordings for your own inspired/personal creative use is a normal home-studio workflow, but the resulting LoRA and its outputs sit in copyright grey territory. Keep it personal-use unless you clear samples.
